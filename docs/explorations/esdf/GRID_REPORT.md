# 共享 float32 节点的规则 C1 距离场

本轮实现了离线 mesh 建图、规则节点保存 / 加载和 CPU / CUDA C1 位置查询。**完整 60×60×15 米地图的体积与查询速度可用；0.2 米间距的几何误差仍明显，不能把接缝连续当作精确避障验收。** 正式调用见 [ESDF 接口](../../../devtools/README.md)，独立审查见 [C1_REVIEW](C1_REVIEW.md)。

## 数据与执行口径

地图为原有 `outputs/mesh_distance_eval/reviewed-20261015/pillar_omni.obj`：seed 23、500 个柱盒、52 对正体积重叠，声明范围 `[-30,30]×[-30,30]×[0,15] m`。完整 OBJ SHA256 为 `da25463989072ef10ceaa5c6cbddd55697c9c16a8d9c2e3c5df3cb5f523ba6e5`。准备得到 5,618 个外露矩形、14,814 个顶点、29,624 个三角形；没有删掉重叠柱或在训练时重建地图。

建图通过公开几何构造柱盒与地面占据并集，在 CPU double BVH 上直接查询所有共享节点，再保存 float32。查询按 Catmull–Rom `a=-0.5` 的三维张量积重建场。当前只支持文档声明的盒并集 / 地面适配与调用方已准备的闭合外露边界，不是任意 mesh 布尔运算器。

项目执行均在 Docker；建图使用 2 CPU / 4 GiB 上限、非 root、无网络容器。主要实验镜像为 `tof-tracker-adaptive-sdf-real-map:torch291`，ID `sha256:2ee12e62ed1cdecba7c214d94cb86ac0bc2edd6654ebd6bf311ed53d9788ce85`，Python 3.12.3、NumPy 2.5.4、Torch 2.9.1+cu128、GCC 13.3。GPU 为 RTX 5070 Ti。通用项目回归另使用已有、依赖匹配的 `tof-tracker-main-sync-d9fc:torch291`，没有改写共享开发镜像。

## 距离精度与符号偏差

独立参考对**并集外露矩形**计算 double 最近距离，符号用盒占据判定；没有把原始被遮住三角形当外露面，也没有用单个物体距离最小值代替并集内部距离。几何构造与早期矩形 oracle 同源，另有不依赖矩形准备或 BVH 的解析盒体、交叉并集、地面与旋转盒回归。

以下为 float64 查询、float32 节点。实际 float32 查询另以其**实际表示的位置**重算 double 参考，主要误差量级相同，原始 JSON 分开保存。

| 样本 | 数量 | 绝对误差 P95 | 最大绝对误差 |
|---|---:|---:|---:|
| 全域均匀点 | 8,192 | 18.00 mm | 72.88 mm |
| 原始柱面附近，包含被遮住的面 | 10,981 | 31.65 mm | 77.93 mm |
| 柱体内部 | 1,000 | 72.39 mm | 82.72 mm |
| 重叠内部 | 156 | 52.43 mm | 84.98 mm |
| 地面附近 | 1,024 | 11.35 mm | 47.25 mm |
| 保存的共享节点 | 2,005 | 0.000098 mm | 0.000226 mm |
| 上述拼接样本 | 23,358 | 31.52 mm | 84.98 mm |

拼接分布刻意偏向表面 / 内部，不能当作全空间均匀统计。节点值准确，主要误差来自间距与平滑插值；真实距离的棱角、中轴不可导区域和窄结构无法由这份粗网格无误差重建。C1 不保证单位梯度，也不保证符号或零面精确。

在 `|真实距离|>1 cm` 的样本中仍有 **161 个符号不符**：143 个真实内部点被插值成正值，另 18 个真实外部点被插值成负值。前者可能高估可用空间，不能统称保守误判。按真值分组，7,783 个内部点的 P95 约 52.49 mm、15,329 个外部点约 20.21 mm；另有表面零值点。没有证明全域最大误差或完成几何精度验收，不能直接保证连续安全净空。缩小间距可配置，但本轮没有跑第二个全图分辨率或擅自确定最终训练安全裕量。

## 接缝与反传

独立 Hermite 实现从共享节点和中心差分导数构建相邻格的多项式，在固定随机节点小场的全部 46 个内部面、414 个面内位置直接比较同一点的左右值及世界梯度。结果值与梯度跳变均为零；CPU / CUDA 八组合同检查通过，包括解析二次函数、float32 与 float64、FD、批次 / 空输入、闭域端点、invalid 零梯度、节点复制隔离、可配置间距和损坏文件拒绝。

全图另抽 384 个内部面位置，以双侧两步线性外推检查极限：值差最大 `3.57e-13 m`，梯度分量差最大 `1.05e-11`。128 个全图位置对插值场的中心 FD 最大差 `2.19e-9`。这些验证的是**插值定义及其梯度**，没有声称等于原始 mesh 在不可导处的唯一梯度。

## 驻留 GPU 查询速度

float32 位置和地图已经驻留 GPU；同步 Python wall time，2 次预热、10 次测量的中位数：

| 点数 | 仅查询 | 查询 + 位置反传 |
|---:|---:|---:|
| 1 | 0.383 ms | 0.924 ms |
| 100,000 | 0.799 ms | 1.169 ms |
| 262,144 | 1.718 ms | 2.402 ms |

不含磁盘、传输、mesh、轨迹解码或整条训练损失。批量复用一次调用，所以不是单点耗时乘点数。262,144 点查询 + 反传的 Torch peak allocated 约 379 MiB，其中相对驻留基线额外约 346 MiB；CUDA 上下文、驱动和其他进程不在该统计内。没有测完整轨迹优化的稳定性或吞吐，也没有做 CUDA 内核融合。

## 复现与证据

- 本报告原建图入口为历史 `just esdf` 命令；该命令已撤回。当前正式调用以 [devtools README](../../../devtools/README.md) 为准，数值仍对应原构建版本。
- 正式 CPU 合同检查：`just check`；CUDA 检查在显式启用 GPU 的容器中运行 `python tests/verify_esdf.py --device cuda --results OUTPUT.json`。
- 实际地图评估：容器中运行 `python -m docs.explorations.esdf.esdf_grid_eval.code.evaluate_map --grid GRID_DIR --map MAP.obj --output NEW_DIR --device cuda`，固定针对上述完整 500 柱参考地图。
- 全图原始数组与结果：`outputs/esdf_grid_eval/full-0p2-20261018/{raw.npz,results.json}`；独立 readback / 原始数组核算另保存在同父目录的 review JSON，不覆盖原始结果。
- [紧凑结果及哈希](esdf_grid_eval/real-map-summary.json)记录构建、误差、时间与原始数据路径。路径积分是[单独小实验](PATH_INTEGRAL_REPORT.md)，未进入正式地图模块。

历史 SdfLib 自适应路线的两次 OOM、主动停止、局部误差及存储膨胀仍保存在[归档](README.md)，本轮没有重跑全图八叉树。
