# 实验开发与审查

本 skill 面向实验需求的开发与审查。已有实验实现的日常运行按其使用入口进行，不因此启动一轮新的实验开发。

先按项目 AGENTS 约定确认任务来源、当前职责和授权范围，再按当前阶段读取：

- 设计或开发实验：[实验开发](references/development.md)。
- 审查实验产出：[实验审查](references/review.md)。

只加载当前阶段需要的内容。两种阶段使用同一份实验依据，包括研究问题、基线、允许改变的空间、评价方式和证据要求。审查默认只读，发现问题不自动转为修复。

## 实验的共同要求

- 每个实验都必须有明确的基线。基线可以来自现有实现、其他分支，也可以专门编写朴素方法。没有现成基线时，建立并验证基线就是实验的第一步；候选方法的比较必须建立在基线结果之上。
- 保持约定的任务含义、信息边界和操作空间。不通过偷用答案、针对评测输入硬编码、跳过应执行的工作或改变输出含义获取指标优势。
- 基线与候选都提供关键条件下的结果，重要收益、退化和失败应有对应分析与证据入口。
- 实验以可信结论和可追溯证据为产出，不以超过基线或合并代码作为唯一成功标准。
- 正式工具化需要重新明确工具任务，并转入工具开发 skill；实验结果不自动成为正式工具。
