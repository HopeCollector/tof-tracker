# 工具开发

## 接收任务

读取工单和相关讨论，确认当前有效的职责、建议接口及结果要求。

对关键缺口提出具体问题或建议。已有明确约定不重复询问；实现细节可以自主完善。需要改变职责或正常调用方式时，显式说明原因及影响。

## 实现与检查

按职责组织实现，检查主要调用关系、信息来源和相关公式。

围绕工单中的使用条件检查最终输出：

- 典型输入是否得到预期结果。
- 重要边界、无效输入和失败情况是否按约定处理。
- 误差与性能是否满足要求。
- 存在状态时，更新、重复调用和重置行为是否正确。
- 是否修改输入、影响共享资源或产生其他相关副作用。

根据需要使用解析情况、独立实现或其他独立依据。基线一致和测试通过数量不能单独证明正确。

## 准备交付

提供可运行的最小例子，展示实际调用、输入和输出。

需要视觉辅助时，按工单范围实现或另行拆分任务，保持它与被测工具的关系清楚。

完成必要验证，并在授权范围内安排独立审查。修复问题后，重新检查受影响的结果。

直接向用户交付实现、检查结果、比较数据和已知限制，按工单约定完成提交、推送和 PR 交付，供用户审阅。
