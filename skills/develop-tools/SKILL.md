# 工具开发与审查

## 什么是一次工具任务

工具任务交付一项可由其他代码调用、或由人操作的能力。它有明确的使用场景、输入输出和职责边界。

例如：距离查询接口、离线数据转换工具、用于人工检查传感器结果的界面。

一次任务可以新增、替换或修复能力，也可以涉及多个模块。任务边界由需要解决的问题和正常使用方式决定。

任务完成后，用户应能够：

- 按推荐方式调用或操作工具。
- 知道工具支持哪些输入和使用条件。
- 查看输出是否正确、误差和耗时是否满足要求。
- 了解相关状态、副作用及使用限制。

## 怎样提出工具工单

工单是协调者、开发者和审查者共同使用的任务依据。可以直接写在委派消息中，不要求每次另建文件。

工单应交代：

1. **问题与使用场景**：谁在什么情况下使用，需要完成什么事情。
2. **职责与修改边界**：本次负责什么，依赖哪些现有能力，哪些相关工作由其他任务承担。
3. **建议接口设计**：给出建议公开的接口、输入输出、必要语义、状态关系和最小调用示例。不要让开发者自行猜测正常调用方式。
4. **结果与性能要求**：说明重要输入条件、预期结果、允许误差，以及需要检查的耗时或资源开销。
5. **比较与检查依据**：有基线时，给出方法、位置和版本。没有现成基线时，说明如何判断输出正确、如何检查基本性能；需要补建比较方法的，应纳入任务范围。
6. **交付内容与任务约束**：明确实现、使用例子、检查结果及必要辅助工具，说明环境和其他特殊限制。

工单应能追溯到实际讨论。用户接手后提出的调整，也应纳入当前任务依据。

## 工单示例：固定网格距离查询

以下示例仅用于说明工单结构，不代表待执行任务。接口、范围、数值和性能目标只属于此例，不是项目统一要求。

### 目标与建议调用

为固定三角网格提供批量点到网格的最近距离查询，返回无符号欧氏距离。

```python
query = MeshDistance(vertices, triangles)
distances = query.distance(points)
```

### 输入输出与状态

- 顶点为 `[V, 3]`，三角形索引为 `[F, 3]`，查询点为 `[N, 3]`，坐标单位为米。
- 查询输入采用 float32，输出为 `[N]` 的 float32 距离。
- 本次支持有效、非空且不含退化三角形的固定网格。
- 构建后几何不变，查询不修改输入，前一次查询不改变后一次结果。

### 正确性与性能要求

在坐标位于 `[-10, 10]` 米的约定范围内，绝对误差不超过 `1e-5` 米。使用解析几何情况及独立朴素实现检查，包括面、边、顶点附近和网格外的点。

在同一 CPU、相同精度和输入下，与朴素逐三角形查询比较。检查 `F=1000`、`N=1024/65536` 的情况，查询耗时中位数不高于基线；构建开销单独报告。

### 交付

实现、最小调用例子、误差与耗时对比、供用户审阅的 PR。比较实现放在测试支撑代码中，不成为正常 API。

## 工具、测试与视觉辅助的关系

公开 API 服务正常使用需求，不为测试便利扩大接口。

公开行为优先通过公开 API 检查。需要访问内部机制时，使用明确归属的夹具，正式模块不反向依赖测试代码。

视觉辅助是一类服务于人工视觉判断的测试工具。人设置输入或场景，触发真实工具运行，通过可视化检查结果。

视觉辅助应有清楚的操作路径、文件归属和依赖关系。它本身也可能复杂到需要单独的工具任务、分支和审查。人工检查覆盖有限，应与其他检查共同使用。
