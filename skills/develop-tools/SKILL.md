# 工具开发与审查

先按项目 AGENTS 约定确认任务来源、当前职责和授权范围，再按当前阶段读取：

- 开发或修复工具：[开发](references/development.md)。
- 审查工具实现或 PR：[审查](references/review.md)。

只加载当前阶段需要的内容。两种阶段使用同一份任务依据，包括职责边界、建议接口和验收主张。审查默认只读，发现问题不自动转为修复。

## 工具的共同要求

- 公开 API 服务正常使用需求，不为测试便利扩大接口。
- 测试和视觉辅助具有明确归属与依赖方向。公开行为优先通过公开 API 验证；需要访问内部机制时，用明确归属的夹具支撑。正式模块不反向依赖这些辅助代码。
- 优先通过命名、类型和结构表达实现，避免复述代码的注释；确有必要时，只记录代码难以表达的约定或原因。
- 文档只维护必要的能力说明、使用约定和最小样例，及时清理过时内容。距离核心贡献越远，修改越克制；无需修改时不改。同一约定只维护一处。
- 正确性与性能主张需要相应证据，证据深度由本次能力和风险决定。与基线一致不能作为唯一正确性依据。
