# 在线 sensor 可视化审查

本工具在浏览器中布置场景、调用正式 GPU sensor，并以浮动窗口检查同次采样的原始数据和最终观测。服务必须持续运行；不生成离线采样网页。

## 启动

在项目根目录运行：

```bash
just build
just review
```

默认浏览器地址为 `http://127.0.0.1:8080/`。Docker 使用 NVIDIA GPU，浏览器使用本机 WebGL。前台退出用 Ctrl+C。工作树使用独立镜像时，build 和运行保持相同标签：

```bash
TOF_TRACKER_DEV_IMAGE=tof-tracker-sensor-review:dev ./docker/dev.sh build
TOF_TRACKER_DEV_IMAGE=tof-tracker-sensor-review:dev ./docker/dev.sh run --web --gpu \
  python tools/sensor_review/server.py --host 0.0.0.0 --port 8080 --map-root outputs
```

地图列表来自启动时指定的目录，可选择已有项目 OBJ，或上传本机 OBJ。只支持项目地图解析器的米制、独立闭合障碍与地面三角网格子集，不加载 OBJ 外部材质/纹理。上传暂存于当前服务会话，不覆盖原文件；换地图会重建 renderer。

## 布置、采样与查看

1. 加载地图。前端显示后端 `MeshMap` 解析的全部几何，不抽稀、不重新生成地图。
2. 选择添加或移动飞机/目标：鼠标按下确定 XY，拖动预览朝向，松开确认。操作锁定当前高度的水平面；高度通过升降按钮调整。飞机朝向保留为完整位姿，工具显示朝向箭头。
3. 放置飞机后点击采样。目标可以不放置，此时不参与遮挡或观测，也不生成隐藏的默认目标。采样调用正式 Warp sensor：四路 ToF 为 8×8、45°/45°、0.015～4m，每格 4×4 子射线选加权 20% 分位；camera 为 160×120，每像素 2×2 子射线，形成最近深度。目标覆盖率、mask 和提示框由外层开发环境模拟。
4. 按需打开子射线距离/ID、归约后的距离/ID、最终距离、camera mask 或覆盖率窗口。窗口支持拖动、缩放、关闭与透明度调整，标题绑定采样编号、传感器和阶段。子射线图展示实际采样网格：ToF 为 32×32，camera 为 320×240；归约图保持各自的输出分辨率。悬停查看物体、距离、选中子射线及代表命中点。解析球没有三角形 ID。NaN 与 inf 保持不同状态。
5. 选择传感器视角，摄像机平滑到达实际安装位姿。平移复用 `devtools.trajectory.fit_trajectory`，浏览器按时间播放；完整旋转使用四元数插值。返回总览可恢复先前浏览位置。
6. 需要叠图时使用贴合视口功能；自由摆放的窗口不自动代表投影对齐。审查视角使用传感器的水平/垂直 FOV 和图像区域，叠图可调透明度及鼠标穿透。归约后的一格由某条真实子射线提供，不一定沿格子中心；浏览器表面光栅化和有限射线的边缘也可能不同，原始二维数据为主要核查依据。

移动设备后旧窗口仍属于旧采样，界面标记过期。重新采样更新当前结果；响应绑定地图 ID、请求 ID、场景版本、位姿和配置，避免异步旧响应冒充当前状态。

## 数据与边界

调用链为 `网页 → HTTP 服务 → 固定 GPU 工作线程 → 公开场景快照 → 正式 sensor 与外层感知模拟 → 显示边界下载`。静态 mesh 共用一份 Warp BVH，目标球使用解析求交；目标位置变化只更新 GPU 球心，不重建 BVH，公开世界坐标几何保持原语义。添加/移除目标改变对象结构，会重建 renderer。浏览器的 WebGL 负责显示，采样核心只需要 CUDA，不调用 OpenGL。

服务在外层 `devtools.rig` 中计算各设备的完整世界位姿，再分别向 `ToFSensor`、`CameraSensor` 登记请求；sensor 本身不知道飞机、安装外参或四路布局。公共 `SensorSampler` 在每个显存分块合并射线、查询核心一次，并按兼容配置批量后处理。相同起点通过起点表和索引共享。即时采样也使用这条管线；开发消费通道允许外层在当前块释放前处理同次原始命中。

服务调用 `devtools.perception.sample_measurement_diagnostics()`，复用这一次采样的原始命中，另外模拟系统提供的目标识别结果。无遮挡目标样本由独立的 Torch 射线—球面解析几何得到，不再发起第二次渲染，也不重复完整相机后处理。诊断保留同次采样数据供窗口检查，过大的诊断请求会提前拒绝。原始图为径向距离和物体身份；RGB 暂不实现。二进制数组以带 dtype/shape 的 base64 传到网页，保留 float32 NaN/inf；仅显示边界做 CPU 下载，生产采样接口保持 CUDA 输出。

ToF 标记为 `weighted_quantile_subrays`，camera 为 `nearest_subrays`。有限采样可能漏掉射线之间的小物体；ToF 即使有少量射线命中目标，也可能在加权归约后选择背景。用子射线图与归约图可以区分这两种情况。外层 mask/覆盖率来自全部可见子射线，因此混合像素的代表深度可以属于另一物体；可见比例的分母是同一组射线在无遮挡目标几何中的合法目标样本数。球体仅是当前开发环境支持的目标几何，不是 sensor 的识别对象定义。

显存执行配置位于 `configs/devtools.json` 的 `sampling_runtime.max_gpu_memory_fraction`，默认 `0.5`，表示采样工作集占整卡显存的目标预算。场景、冻结位姿、计划保留输出和一个分块的临时数据都计入；同时考虑当前可用显存与安全余量，自动选择分块大小。它不是整个训练进程的硬限额，也不负责释放调用方持有的其他输出。场景或最终结果本身超过预算时会明确报错。每批次固定同一场景版本，目标更新发生在登记请求之前。采样结果的元数据展示执行预算和实际分块信息。外层识别门限单独位于 `perception.min_visible_fraction`。

`hit_point_sensor_m[H,W,3]` 是选中射线的实际传感器 FLU 命中点，不能用归约距离乘中心方向恢复它。所有距离均沿射线计米。已知无回波为 +inf；缺少地图域的无回波、未知采样段或选中太近表面为 NaN。任一未知子射线使该格测量不可用。前端射线只用于鼠标布置和选中实体，不计算 sensor 观测。

工具支持一个会话、一架飞机、一个可选目标。当前没有扰动；方向扰动应发生在核心之前，回波和测量扰动应发生在核心之后。工具不模拟真实 RGB 外观、信号积分或多路径，不执行飞行轨迹或碰撞规划。启动服务只绑定本机回环发布的 Docker 端口，不暴露任意工作区文件。

Three.js 0.180.0 模块及 MIT 许可在 Docker 构建时按固定 SHA-512 校验并安装，浏览器运行时从同一服务加载，无外部 CDN。固定 Warp 1.15.0（Apache-2.0）提供 mesh BVH/ray query，与 Torch 共用 CUDA 存储和 stream；未复制 Warp 原生源码。

## 验证

```bash
just check
just check-sensors
just check-review
```

`verify_ray_review.py` 通过实际 HTTP 请求和独立 CPU 几何 oracle 验证地图与上传、原始子射线、归约和覆盖率、目标更新、错误请求和轨迹端点。`verify_ray_sensors.py` 检查核心几何、跨 stream、量程与后处理。交互仍需在浏览器检查放置手势、窗口操作、视角过渡和透明叠图；结果保存在 `outputs/`，不在本文累计运行记录。旧渲染实现和性能资料见[探索档案](../../docs/rendering-exploration/README.md)。
