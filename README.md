# tof-tracker

基于四路 ToF、自身运动状态和前向目标提示的三维局部追踪算法。开发目标包括接近目标、避障、主动调整航向、提前减速，以及输出目标方位、置信度和稳定的接管请求。这些能力尚未实现。

**最终只交付算法：模型及其输入适配、轨迹处理、选轨和判断逻辑。** 训练、场景、传感器、几何查询与闭环实验都用于开发算法，放在同一仓库中按职责划分模块，不作为额外交付项目。需要部署的算法工程部分采用可在 C++ 中运行的实现，交付运行路径不要求 Python。

## 开发工具各自做什么

### 场景生成与场景表示

地图生成工具独立离线运行，输出约定格式的地图资产。优先适配 mockamap 或旧工程中已采用的生成机制，让工具服从本项目的参数、数据格式和职责。训练读取已准备的资产，不调用地图生成器，也不把它接入训练流水线。

`devtools/scene.py` 负责加载和表达物理场景，包括背景、指定目标、其他实体及实验所需真值。传感器与几何查询使用同一份物理场景；目标不能只出现在相机提示里而从 ToF 或避障几何中消失。用于代价的安全膨胀不渲染成真实物体。

### 传感器

`devtools/sensors.py` 在指定机体位姿下生成 ToF 和相机观测。批量采样时可以逐次指定不同场景和位姿，飞机无需经过动力学飞到这些位置。以后闭环评价也可使用相同观测接口，由实验执行端提供当前位姿。

ToF 渲染与目标投影可以参考旧 YOPO 的计算机制，传感器规格和 mask 语义按本项目重新明确。旧实现中的投影矩形不能直接视为经过逐像素遮挡判断的可见目标 mask。

### 样本读取

`training/dataset.py` 读取样本记录、必要的场景关联信息并组织批次，供 DataLoader 或直接迭代使用。这里的“数据工具”就是样本读取与组批，无需单独建立数据平台。

采什么场景、位姿、运动状态和目标条件，以及它们的分布，是训练配方。样本可来自离线生成的观测，也可由公开的场景与传感器接口按配方生成；读取器不隐藏地图生成、动力学执行或任务代价计算。

### ESDF 与几何查询

`devtools/esdf.py` 负责距离场的构建、加载、批量距离查询及训练需要的导数。具体距离场后端在实现时选择；模块名不要求照搬旧实现。

例如，它回答“这些轨迹采样点离物体表面多远”，训练代码再将距离转成安全惩罚并决定权重。几何工具不决定追踪目标、损失组合或优化更新。查询通过公开接口保留计算图或提供明确导数，逐条验证需要的梯度。

### 训练

`training/train.py` 先保持为直接可读的训练入口：取批次、模型前向、轨迹解码、计算分项代价、反传、更新、记录与保存。代价函数在开始实现对应能力时加入，不提前搭建通用 Trainer 框架。

主训练路线采用 YOPO 的批量采样和可微轨迹代价。传感器观测、场景几何和监督真值服务这条链路；无需在每次参数更新前把飞机闭环飞一遍，也不组织成动作、奖励与 episode 的强化学习流程。

### 闭环评价

闭环评价用于观察算法在连续执行、控制和动力学影响下的行为，单独组织实验。优先复用现有的控制与动力学实现或合适的模拟器，再以适配层接入观测和算法输出；当前尚未选择具体方案。

若以后需要 `sim` 模块，它负责实验执行、状态推进和公开观测接口。实验场景、配置与记录可以组成测试夹具，但不因此恢复一个统管训练和工具的总包。项目内部当前不引入 ROS 运行依赖；外部闭环测试方案需另行讨论。

## 调用关系与边界

计划中的批量训练链路：

```text
已准备的地图 / 样本资产
    ↓
training：采样配方、样本读取与组批
    ↔ devtools：场景、指定位姿观测、监督真值
    ↓ 仅将约定观测送入模型
tof_tracker：模型前向与轨迹生成
    ↓
training：任务代价
    ↔ devtools：公开的批量几何查询与导数
    ↓
training：反传、参数更新与保存
```

计划中的闭环评价链路：实验执行端推进状态 → 传感器观测 → 算法推理与选轨 → 控制执行 → 下一次观测。真值只用于评价和解释结果。

训练可以调用算法与开发工具，但不直接读取工具的内部地图、实体存储或渲染缓存。世界位姿与目标真值可用于监督、坐标转换和评价，不能补入在线模型观测。在线算法核心不导入 `training` 或 `devtools`，不加载地图或模拟器。

真实系统负责采集同步、世界状态、轨迹重建执行、底层飞控、实际权限与悬停控制。算法提出接管请求，实际切权和恢复由系统决定。研发与训练以 Python 为主；模块优先直接调用函数或库，通信机制在确有并发或隔离需求时再加入。

## 当前接口依据

输入以参考时刻的真实本体 FLU 表达：X 向前、Y 向左、Z 向上。本体 Z 不要求与世界 Z 对齐，不将观测回正到水平系，也不删除上下方向信息。

| 输入字段 | 含义 |
|---|---|
| `t_ref` | 测量参考时间；结果关联并回传该时间 |
| `tof_m` | 四路 8×8 米制距离；包顺序为右、前、左、后 |
| `state_b` | 本体平移速度与加速度，顺序为 `vx, vy, vz, ax, ay, az` |
| `target_hint` | 观测置信度与四个归一化框边界，共五个数 |

ToF 按 `row * 8 + col` 展开，行向下、列向右。若复用旧 Omni 模型的前、左、右、后布局，由算法适配层显式重排；新模型布局在实现时明确。模型归一化也在适配层处理。静止时平移加速度为零，不能直接使用含重力的原始 IMU 读数。

目标提示为 `[confidence, u_min/W, v_min/H, u_max_exclusive/W, v_max_exclusive/H]`。未检出时为五个零；几何核查阶段可以产生 0/1 置信度，字段本身支持 `[0, 1]`。该置信度与后续算法输出的方位置信度含义不同。

输出开发目标是配套的三维平移末状态、主动航向末状态、目标三维方位与置信度，以及稳定的 0/1 接管请求。网络结构、候选生成、近距监督和滤波方法尚未确定。

## 近期建设顺序

| 检查点 | 建设内容 | 审阅依据 |
|---|---|---|
| 一帧观测 | 输入定义、最小场景、四路 ToF、前向目标 mask 与紧凑提示 | 物体如何形成观测，深度格子的来源，遮挡与姿态的影响 |
| 一条轨迹 | 三维轨迹重建、平滑代价、几何查询与行为评价 | 曲线、速度变化和分项代价；解析与独立几何检查 |
| 第一次学习 | 模型骨干、少量样本、训练循环、保存重载与固定评价 | 参数确实更新，输出变化可解释，重载一致 |

模型形成稳定的完整前向后，在大量训练前与系统侧检查一次目标工具链转换能力。实际平台部署由系统侧负责。

第一检查点只摆放一个目标、一个障碍和一个带四路 ToF 与前向相机的机体。指定静态位姿，依次检查：

1. 目标在前方、障碍在侧面。
2. 只移动障碍，让它遮挡目标。
3. 改变机体俯仰或横滚，检查真实姿态引起的观测变化。

这一轮关闭噪声核查几何。ToF、目标 mask 和遮挡来自同一场景，不能手填深度图。开发工具保留射线命中及真值用于解释结果，算法只能收到约定的观测。

实现前需要明确传感器安装姿态、视场、格子采样与距离含义、量程和无返回编码，以及 mask 到框的遮挡规则。旧 C5 近距路径的“2 米有效、4 米无返回”不是新项目已确定的规格；最大填充值也不能解释为已知空闲。
