# 训练

`training` 负责采样配方、任务监督、损失、反传与参数更新，不进入算法交付运行路径。当前 `train.py` 和 `dataset.py` 都只有职责占位；没有可运行的训练入口，直接执行不会生成训练结果。

## 主训练链路

主路线采用 YOPO 的批量采样与可微轨迹代价。以下链路尚未实现：

```text
已准备的地图 / 样本资产
    ↓
training：按采样配方读取或生成样本、组批
    ↔ devtools：场景、指定位姿观测、监督真值
    ↓ 仅将约定观测送入模型
tof_tracker：模型前向，输出终点状态
    ↓
devtools：轨迹解析与采样
    ↓
training：任务代价
    ↔ devtools：公开的批量几何查询与导数
    ↓
training：反传、参数更新与保存
```

`train.py` 的职责是取批次、模型前向、调用 devtools 解析轨迹、计算分项代价、反传、更新、记录与保存。代价函数随对应能力加入，当前不建立通用 Trainer 框架。参数更新前无需闭环飞行，不组织成动作、奖励与 episode 的强化学习流程。

## 样本与几何边界

采什么场景、位姿、运动状态和目标条件，以及它们的分布，由训练配方决定。`dataset.py` 只读取样本记录、必要的场景关联信息并组织批次，供 DataLoader 或直接迭代使用。样本可来自离线观测，也可按配方通过公开场景与传感器接口生成；读取器不隐藏地图生成、动力学执行或任务代价。

地图生成器独立离线准备资产，训练读取已准备的数据，不在训练循环中调用生成器。开发工具提供场景、观测、真值和几何事实，职责及当前接口见 [devtools](../devtools/README.md)。

训练通过公开数据与查询接口访问开发工具，不直接读取内部地图、实体存储或渲染状态。例如，几何查询回答轨迹采样点离物体表面多远；训练将距离转为安全惩罚并决定权重。查询应保留计算图或提供明确导数，所需梯度逐条验证。

世界位姿与目标真值可以用于监督、坐标转换和评价；模型前向只接收 [算法输入约定](../src/tof_tracker/README.md#输入约定)，不能补入世界真值或物体身份。

## 闭环评价

闭环评价单独观察连续执行、控制与动力学影响下的行为，不藏进样本读取或损失计算。计划链路是：实验执行端推进状态 → 传感器观测 → 算法推理与选轨 → 控制执行 → 下一次观测，真值只用于评价和解释。

研发、训练与测试在 Docker 中执行，运行环境见 [docker/README.md](../docker/README.md)。返回 [项目入口](../README.md)；实际提取来源见 [docs/origins.md](../docs/origins.md)。
