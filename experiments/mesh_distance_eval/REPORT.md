## 几何与梯度的结论

通过 `Scene.from_obj()` 和 `get_geometry(exclude_ids={"vehicle"})` 读取完整静态 OBJ、开放地面和精确目标球。没有读取 scene 内部存储，没有加入飞机，也没有把世界真值补进在线算法。距离量到连续三角面/球面，不是占据格中心。

| 验证对象 | 结果及边界 |
| --- | --- |
| 解析盒与独立三角面 oracle | oracle 自检 256 点最大差 `2.22e-16 m`；面内、边、顶点、内部、近面、窄缝及完整三维旋转验证通过 |
| 项目真实柱场 | 每场独立 exhaustive float64 oracle 检查 256 点；稳定 A 最大差 medium `4.86e-7 m`、完整柱场 `9.90e-7 m`；原生 A 分别 `9.37e-7 / 2.42e-6 m` |
| 解析球与三角化球 | 目标使用精确球公式；另设 320 面球的三角面查询对照，球网格近似误差单列，未当作算法误差 |
| Torch 链路 | 两条 A 和 B 均完成 `参数 → 三维变换后位置 → 距离 → exp 代价 → SGD`；参数有限差分最大差 A `4.04e-5`、B `4.93e-5`；5 次更新代价持续下降 |
| B 的导数 | 对自身三线性插值，有限差分最大差约 `0.001084`（float32、步长 `1e-4 m`）；独立小场景相对连续几何梯度偏差最大约 `0.0411`，两项主张分开 |
| 动态目标 | 5 次移动包含与柱体重叠及离开；A 值、B 全格与查询逐阶段对照 fresh 一致，静态 BVH handle 保留，旧位置影响消失 |
| 有效域与输入 | NaN/Inf、地图范围外、场支撑外输出 NaN/零梯度；有限地面边缘、完整 XYZ 和场边界检查通过；没有 padding 墙或隐式自由空间 |

独立验证 **101/101 项通过**，数值审查回归 **7/7 项通过**。这个计数包含“反例被准确暴露”“不支持输入被拒绝”，不表示以下能力已实现：

- **重叠内部精确距离未支持。** 两个十字盒中心到真实并集边界为 `-0.70710678 m`；拼接原始 mesh 的 signed distance 和 `min(实体 SDF)` 均为 `-0.5 m`。绕数在该例内外符号正确，伪法线符号在 7 点中错了 2 点。正确符号不能去除内部埋藏面。
- **原生 Tape 的近表面导数未通过准确性主张。** 普通尺度、世界坐标偏移的解析盒，距面约 `20 μm` 时梯度分量最大误差 `0.409`；距面 `0.1 / 1 mm` 时分别约 `0.0347 / 0.000284`，距面 `0.1 m` 时约 `5.96e-8`。稳定 A 在这些探针上符合 float32 表示的解析距离和梯度。随机完整柱场中 A 两路最大梯度差 `0.0132`，medium 为 `0.0909`；不能用其极小均值隐藏局部差异。
- **B 可能漏掉亚格障碍。** 厚 `0.02 m` 的盒体放在 `0.1 m` 节点间，内部真实距离 `-0.01 m`，插值却为约 `+0.032 m`。本项目最小柱宽、边缘裁剪、所需安全误差必须参与格距选择。
- **极薄/float32 退化三角形未支持。** 原生最近面选择已复现错误；现在以 `cross_norm / longest_edge² < 1e-3` 明确拒绝。该判据不构成任意 mesh 的精度证明。局部 Torch 重算已修复 Gram 行列式消去与 NaN 梯度，但不能修复原生搜索选错的三角面。

最近特征切换、接触、棱角和中轴处可能没有唯一导数。这里只验证位置一阶导数；不承诺顶点梯度、二阶梯度或任意网格的数学精确性。

## 同任务性能

RTX 5070 Ti / 16 GiB、Ryzen 7 9700X、驱动 595.91.07；Ubuntu 24.04、Python 3.12.3、Torch `2.7.1+cu128`、Warp `1.15.0`（wheel 内核 CUDA 12.9）、NumPy 2.2.6、trimesh 4.8.3、GCC 13.3。可移植镜像 ID 为 `sha256:95717ec134c0d21420e5db99b7f19f4637856c22466ec60357c7097a6782833f`，大小约 12.2 GB；没有 ROS/nvblox 运行依赖，也不要求 nvcc。

同步墙钟计时：3 次预热、15 次测量，表内为中位数。查询输入/场已在 GPU，不含上传/下载；`距离+代价+反传` 是完整 forward + `mean(exp(-d))` + 对位置 backward，**不是纯 backward**。A 均含绕数判符号；A_torch 对选定三角形用 float64 稳定重算并输出 float32。B 以无 Tape 记录的原生 Warp 查询采样，继承其近面数值误差，同一几何语义不等于 bitwise 同一函数。

首例首次 A_torch 距离调用 `762.226 ms`，含 JIT/module load 和首次 Torch 运算；Warp 编译日志约 `0.75 s`。首次 Tape 完整链路 `35.742 ms`、首次 B 建场 `2.549 ms` 也单列，不能混入稳态表；后续两个场景复用已编译 kernel。首次几何准备计时不是纯 BVH kernel 时间。

场在完整地图的 cell 中心采样：medium 从 `(-15.9,-15.9,0.1)` 到 `(15.9,15.9,8.7)`，完整柱场从 `(-29.9,-29.9,0.1)` 到 `(29.9,29.9,14.9)`。A/B 比较点均位于该支撑域；地图边缘外半格对 B 无效，没有缩小地图后冒充全域场。

目标更新是已有快照到三维球中心 GPU 张量的替换，静态 BVH/几何复用，不是移动全部静态 mesh。`Scene.with_target_position()+get_geometry()` 另计，两个柱场约 `0.382 / 0.381 ms`；B 更新表含 backend 替换和全采样，不含该 CPU 快照构造。动态验证每步与 fresh 对照，没有宣称局部增量场。

65,536 点上传约 `0.09–0.16 ms`。B 直接在 GPU 构建，没有必须上传的 CPU 距离场；可选下载/重上传单列，medium 为 `0.281 / 0.272 ms`，完整场为 `2.506 / 1.910 ms`，均为单次观测，不是稳态传输基准。

## 栅格误差与显存

65,536 个相同随机点，B 对稳定 A 的距离差：

| 场景 | 最大绝对误差 m | p95 绝对误差 m | 最大高估 m |
| --- | ---: | ---: | ---: |
| 解析盒 | 0.155991 | 0.016606 | 0.155991 |
| medium | 0.114101 | 0.043673 | 0.103362 |
| 完整柱场 | 0.102761 | 0.029740 | 0.102761 |

这些是插值相对本实验连续几何语义的误差，不是并集内部精确距离误差。B 与原生 A 的梯度分量差最大可达 medium `1.94`、完整柱场 `1.87`；最近特征切换和插值单元有不同局部梯度，不能只凭反传接通推断几何导数一致。

单份 field 为 medium `4.297 MiB`、完整场 `25.749 MiB`；当前实现保留 XYZ 值和 ZYX 连续查询副本两份。两个柱场顶点/索引分别约 `0.046 / 0.069 MiB`，另有 BVH 和运行时开销。

每路线另启一个新进程，以 CUDA context 初始化后为基线。全局 CUDA free 差包含缓存和宿主活动，**不是精确进程峰值**；Torch allocator 的峰值只含稳定查询/反传，不含首次 B 采样峰值，也不含 Warp 分配：

| 场景 / 路线 | 准备后全局占用增量 MiB | 查询反传后全局占用增量 MiB | Torch 查询峰值增量 MiB |
| --- | ---: | ---: | ---: |
| medium / A_torch | 80.0 | 138.0 | 37.99 |
| medium / A_tape | 80.0 | 90.0 | 7.81 |
| medium / B | 121.31 | 123.31 | 11.77 |
| 完整柱场 / A_torch | 80.0 | 138.0 | 37.99 |
| 完整柱场 / A_tape | 80.0 | 90.0 | 7.81 |
| 完整柱场 / B | 254.94 | 258.06 | 55.18 |

未对 Warp/首次采样整体峰值作完整 instrumentation，不据此给显存硬上限。A_torch 的 double 临时量会增加训练查询显存；B 的全格节点和缓存还会增加准备阶段压力。

## 选择与正式接入成本

| 路线 | 适合的条件 | 尚需正式解决的内容 |
| --- | --- | --- |
| A_torch | 连续表面精度、频繁目标更新、先建立可解释的训练参考 | 明确允许的重叠语义；公开 query/valid 合同与批量形状；固定 mesh 质量和坐标精度；训练集成与异常回归 |
| A_tape | 作为融合 kernel/Torch 桥接对照，较小良好场景 | 近面精度未通过；大柱场 Tape backward 比 A_torch 更慢，当前没有采用优势证据 |
| B | 允许栅格误差，同一静态场景有足够多训练查询可摊销 | 格距/安全误差/薄障碍规则、缓存与序列化、更新预算、场有效域与两份存储 |

按本轮 65,536 点完整链路中位数估算，仅摊销建场计算需要 medium 约 **10 批**、完整柱场约 **52 批**；这是算术估算，尚未计 I/O/训练其他部分，也没有解决误差与薄障碍要求。目标每批移动时，当前 B 全量重采样成本不能忽略。静态场与解析动态球分开查询可作为后续可测方案，但本实验没有实现或计量该变体。

正式接入只需要本实验核心库和明确接口，不需要整个 PhysicsNeMo 框架。该官方封装每次建 BVH，且 backward 刚在固定 main 源码中加入；Kaolin 是全三角面遍历，二者都未作本次运行基准。粗略工程估计（熟悉 Torch/CUDA 的单人、沿用当前语义和已有场景）A_torch 约 `3–6 人日`、B 约 `4–8 人日`，涵盖接口/valid、生命周期/版本、针对训练的集成和回归；不是实测工时，不包含精确并集工程。

若必须准确量到并集外露边界，应先解决几何布尔。成熟 Manifold3D 可离线合并静态闭合柱体，再随动态实体重新布尔、导出并重建 BVH；它是 CPU/TBB 路线，开放地面必须分开，球三角化还引入形状误差。该路线只查了官方源码，未安装/计量，不能给动态预算或可靠工期。也不能把它称为解析球并集的数学精确 SDF，详见[调研](RESEARCH.md#后续若需要实体并集外边界)。

已有 nvblox 数字对应占据/异类格中心及不同计时范围，不与这里的 mesh 表面距离作等价速度比较，本实验没有重复修复 nvblox。正式路线仍需围绕允许的内部语义、局部高估、薄障碍与更新频率讨论。
