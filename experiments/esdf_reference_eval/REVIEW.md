# 独立审查：参考 ESDF 与 C1 轨迹损失

审查对象是同一受控地图和固定 120 条曲线上的实验结论。当前未发现阻止交付这一实验的计算或比较口径问题。证据支持：共同 30 点目标下，C1 的损失及大多数轨迹的参数梯度更接近独立 mesh 参考；它仍有局部误差，当前实现耗时也高于参考路径。本实验不能证明真实训练、轨迹优化或飞行结果已经改善。

## 审查范围和执行隔离

只读审查 `reference.py`、`build_maps.py`、`fixtures.py`、`oracle.py`、`evaluate.py`、`verify_float32.py` 和 `run.sh`；未修改这些实现。独立补充执行全部在既有 Docker 镜像的 CPU 中完成，没有重跑 GPU：

- 比对固定参考源码的七个原方法，方法源码逐字一致。
- 从保存的 NPZ 独立重算全部损失/梯度汇总、最终收敛标志、时间/空间分量、候选排序及 36 行计时的中位数/P95。
- 用 NumPy 幂级数重新构造全部 3,600 个查询位置，再调用现有 CPU triangle BVH，核对矩形 oracle 的距离与损失。
- 检查端到端 v2 重放与 v1 的所有 82 个原始数组、EDT/occupancy 文件及当前源码哈希。

oracle 的解析几何、FD 和积分测试由几何 agent 执行；fixture 的端点及 Bernstein 检查由研究 agent 执行。审查者读取了其测试实现和原始结果，未将这些运行冒充为独立重跑。

## 比较口径

固定参考为 YOPO-tracker `89c4d6f9140c269c58a6e5dc3fe6b93b58580219`，源码 SHA256 为 `bcc8adbc607a1c7e764aa7f69fb71f524245f7aa21fb79a2d48765e85610d52b`。原 float32 系数求解、原 crop/`.tolist()` 同步、`grid_sample` 及 clamp 均保留。新的显式数组构造器不依赖原训练工程。

在已检查的参考路径中未找到与当前 OBJ 匹配的训练 PLY，因此当前输入是相同 OBJ 的原始盒面与地面采样，包含重叠内部面。这是受控输入实验，不是原数据集、随机 generator 或 PCL 体素滤波的复现。参考占据只来自表面点，双 EDT 不会自动填满实体内部；这部分几何表达差异正是第一条路径的被测内容。

同节点三线性控制组有必要：它与 C1 共用同一份 float32 mesh 距离节点，保留参考 query/crop，从而避免把全部差异归因于插值阶数。原索引原点未加半格“修正”；这忠实于原实现，但不宣称原点本身是几何精度最优的约定。

三条精度主路径共享固定 T=10/6、120 条 float64 五次轨迹、相同 penalty、相同 `u=k/30` 右端点和 mean。这里不是乘 T 的物理时间积分。末端参数按 p/v/a 三组三维量分别比较，避免混量纲的九维夹角。独立 mesh 参数梯度使用五次曲线边界敏感度公式，而非再次调用被测拟合函数的 backward。

所有曲线的完整 Bernstein hull 位于 C1 有效域与原参考真实节点支撑内。30 点及最终 dense 查询的参考 clamp 次数均为零。30 点 mesh oracle 没有不同最近特征梯度的 tie，涉及 0/120 条轨迹。

## 从原始数组确认的结果

共同 30 点 mesh 目标下，损失相对误差为：

| 路径 | 中位数 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| 参考表面 PLY / EDT / 三线性 | 7.0677% | 20.1249% | 22.3308% |
| 同 mesh 节点 / 三线性 | 1.0750% | 2.1334% | 3.6454% |
| 同 mesh 节点 / C1 | 0.1487% | 0.9069% | 1.5787% |

C1 比参考的逐轨迹损失绝对误差低 118/120 条，比同节点三线性低 115/120 条。结论不是每条曲线都占优。参考/Same-node/C1 的 3,600 点距离误差 P95 分别为 0.26007/0.03205/0.02122 m；在 `|d_mesh|>0.01 m` 时的符号错误分别为 370/5/3 点。

共同 30 点的末端 p/v/a 梯度夹角 P95 分别为：参考 105.85°/141.77°/155.90°，同节点三线性 26.98°/73.82°/88.99°，C1 16.00°/36.48°/54.34°。C1 的加速度梯度仍有 3/120 条与 mesh 梯度夹角大于 90°。FD 通过只说明被测目标的导数连通且数值一致，不能覆盖这些几何梯度偏差。

梯度角度与范数误差也不能混为一个指标：同节点三线性/C1 的末端位置梯度相对 L2 误差 P95 为 58.1%/60.4%，这个尾部指标上 C1 没有胜出。

另对实际 float32 fit/Horner 位置上的 float32 penalty 与九参数梯度做了核验；空间 oracle 在相同可表示位置内部使用 double。保存的八个 cost/gradient 数组均为有限 float32，独立重算与 JSON 的全部指标一致。参考/同节点三线性/C1 的 loss 相对误差 P95 为 20.12490%/2.13343%/0.90690%，支持主表的舍入结论。这一补测把精度对照接到计时使用的 dtype，不证明任意 float32 位置均不会出现数值或几何反例。

## 时间求积和候选选择边界

最终数值参考为每段八点 Gauss、512 段、4,096 点/曲线，并保留前三级结果。所有路径的 120 个 loss 均满足最后一级差分准则；mesh/参考/同节点三线性/C1 的梯度满足数分别为 116/102/120/120。准则仅比较相邻两档，不是严格积分误差上界。dense mesh 有 866 个 tie 样点，不能把其分支梯度写成处处唯一的连续几何梯度。

mesh 未通过梯度准则的四条为 `(2,3),(2,4),(2,5),(6,6)`。排除这四条的敏感性分析没有改变主趋势：对 dense 目标的末端 p 梯度相对 L2 误差 P95，参考/同节点三线性/C1 为 233.48%/45.24%/28.16%，全 120 条时为 249.53%/58.43%/30.78%。主表使用共同 30 点目标，避免将未充分收敛的连续梯度当作主真值。

即便使用 mesh 距离，30 点 mean 相对 dense mesh loss 的误差中位数/P95 仍为 0.4849%/1.5158%。C1 的空间与时间分量绝对值 P95 分别为 0.6620% 和 1.2828%（统一除以 dense mesh loss）。每条曲线的有符号误差严格相加；不能相加两个 P95 或两个绝对值来得到最终误差。

在每组 15 候选的排序中，参考有 109 对、同节点三线性有 4 对、C1 有 0 对非并列候选次序相反。这些 pair 的 mesh loss 差超过最后一级两条曲线的差分量之和，仍只是稳定性检查而非认证边界。**所有八组最终选出的候选，其 dense mesh loss 都等于组内最优值。** 部分 candidate ID 不同是相同最优值的并列；本批不能宣称最终候选选择或优化效果已改善。

## 性能结论的有效范围

v2 的 36 个计时行都能由其 12 次保存 wall time 重算得到。计时是 float32、驻留地图、两次预热后的 Python 同步 wall clock；它包含各方法实际 query、crop 和同步成本，不包含离线构图、加载、传输、独立 oracle 或优化器。`backward=true` 计入 forward 和 backward，不能读成纯 backward 时间。额外 peak allocated 也不代表地图常驻大小或总进程显存。

例如 B=8、K=15、N=30：已解码系数路径的 forward+backward，参考为 0.695 ms、同节点三线性 0.723 ms、C1 1.262 ms；完整初末状态路径为 0.951/2.357/2.680 ms。完整路径中，参考执行固定公式原 forward，而本项目执行公开 fit/sample 和其输入验证及状态采样，不能把两者全链差额全归因于 C1 插值。未保存冷启动计时，不能把这组数据用于首次调用延迟。

这些是同一张地图上的重复场景批次和固定几何锚点。12 次重复不构成稳定性能置信区间，8×15 个受控压力样本也不是训练分布抽样。本轮未测试正式训练后端。
